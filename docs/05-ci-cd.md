# CI/CD и развёртывание

## Решение

**CI/CD и деплой в рамках проекта не делаем.** Проект учебный, сдаём его как код в репозитории с локальным запуском через Docker Compose. Промышленного развёртывания (PreProd/Prod) не будет.

Правила про CI/CD и окружения из `04-git-workflow.md` (п. 3–4) считаются целевой моделью «на будущее», а не обязательством спринтов.

## Что делаем вместо этого

* Проверки перед PR делаем руками: сборка, линтер, юнит-тесты локально (`ruff check`, `ruff format --check`, `python -m unittest discover -s tests -t .`).
* Ревьюер в PR подтверждает, что прогнал тесты у себя.
* Локальный стенд — `docker compose up` (app + PostgreSQL), тестовая БД отдельная.

## Если развёртывание понадобится

| Что | Инструмент | Зачем |
|---|---|---|
| Git-хостинг + CI | **Gitea** (self-hosted) + Gitea Actions | свой сервер, защищённые ветки и обязательные проверки без платных тарифов; Actions совместимы с синтаксисом GitHub Actions |
| Управление контейнерами | **Arcane** | веб-панель для Docker и Docker Compose: запуск стеков, логи, обновление образов без ручного SSH |

Схема в этом случае: репозиторий зеркалится или переезжает в Gitea → Gitea Actions собирает и тестирует → образ разворачивается как Compose-стек через Arcane на одном сервере.

Чтобы переезд был безболезненным, уже сейчас держим:

* `Dockerfile` и `docker-compose.yml` в корне;
* `.env.example` со всеми переменными, секреты только в `.env`;
* сборку и тесты одной командой;
* health-check `GET /health`.
