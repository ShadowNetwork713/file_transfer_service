# Сценарии демо и критерии приёмки спринта 3

Запуск демо: `python -m app.demo` (между сценариями пауза по Enter) или `python -m app.demo --no-pause`. Данные лежат в `data/demo`, `chain.json` после каждого сценария с подменой возвращается в исходное состояние. Демо показывается на версии из `main` (см. `sprint-3.md`, задачи лида).

## 7 обязательных сценариев

### Сценарий 1. Создание нового блокчейна с genesis-блоком

* **Действие:** программа создаёт пустую цепочку и сохраняет `chain.json`.
* **Что видно на экране:** блок 0: `prevHash` из нулей, записей нет, хеш `1c9a8033388f13fa...`; пояснение, что genesis создан вручную.
* **Ожидаемо:** файл цепочки создан, в нём один блок.

### Сценарий 2. Добавление записей и блоков, хеши и связи

* **Действие:** регистрируются три документа: `contract.pdf`, `report.docx`, `notes.txt`.
* **Что видно:** для каждого статус `CONFIRMED` и номер блока 1, 2, 3; `prevHash`, запись с `recordHash` и `hash` блока; строка «prevHash равен hash блока N-1: True».
* **Ожидаемо:** `prevHash` каждого блока равен хешу предыдущего.

### Сценарий 3. Сохранение, перезапуск и восстановление

* **Действие:** программа показывает размер `chain.json` и заново читает цепочку из файла.
* **Что видно:** «Восстановлено блоков: 4, содержимое совпадает: True» и хеши всех блоков.
* **Ожидаемо:** после «перезапуска» цепочка та же.

### Сценарий 4. Проверка валидности корректной цепочки

* **Действие:** проверка цепочки по FR-17.
* **Что видно:** «цепочка валидна, нарушений нет».

### Сценарий 5. Изменение содержимого записи

* **Действие:** в `chain.json` меняется `fileHash` записи в блоке 2, цепочка загружается заново.
* **Что видно:** строка из лога, «цепочка НЕ валидна, нарушений: 1», «Проблемный блок: 2», причина «запись изменена, хеш записи не совпадает с пересчитанным», ожидаемое и найденное значение.
* **Ожидаемо:** называется блок 2 и причина (`RECORD_HASH_MISMATCH`).

### Сценарий 6. Изменение хеша предыдущего блока

* **Действие:** в `chain.json` меняется `hash` блока 2, у блока 3 `prevHash` остаётся прежним.
* **Что видно:** «нарушений: 2»: блок 2 «хеш блока не совпадает с пересчитанным» и блок 3 «prevHash не совпадает с хешем блока 2»; пояснение «цепочка разорвана».
* **Ожидаемо:** точка разрыва в блоке 2, разрыв связи у блока 3 (`BLOCK_HASH_MISMATCH` и `PREV_HASH_MISMATCH`).

### Сценарий 7. Проверка внешнего файла

* **Действие:** файл `contract.pdf` сверяется с записью трижды: без изменений; с изменённой суммой; для неизвестного документа.
* **Что видно:** `VALID` с блоком 1; `INVALID` и разные хеши в записи и у файла; `NOT_FOUND`.
* **Ожидаемо:** изменение даже одного символа даёт `INVALID`.

## Критерии приёмки спринта 3

Критерий выполнен, если его проверяет автоматический тест (`tests/`) или сценарий выше.

### Отчёт валидации (SER-67)

1. Отчёт перечисляет все нарушения, а не только первое.
2. На целой цепочке отчёт пустой, `validate_chain` возвращает `True`.
3. В каждом нарушении есть номер блока, код, сообщение, ожидаемое и найденное значение.
4. Проверяются хеш блока, `prevHash`, хеш записи, номер блока и genesis.
5. `validate_chain` согласован с отчётом и возвращает `False`, если цепочка заблокирована.

### Точка разрыва (SER-68)

1. `find_break` возвращает первое нарушение, на целой цепочке `None`.
2. Сообщение называет блок и причину.
3. При загрузке `chain.json` строка с блоком и причиной пишется в лог, добавление блоков блокируется.
4. Отказ добавить блок (`InvalidChainError`) называет блок и причину.

### Проверка файла (SER-69)

1. Неизменённый файл даёт `VALID`, изменённый `INVALID`, неизвестный документ `NOT_FOUND`.
2. На повреждённой цепочке результат `CHAIN_INVALID` с указанием блока.
3. При нескольких регистрациях документа файл сверяется с последней.
4. В результате есть хеш файла, зарегистрированный хеш и номер блока.

### Демо-программа (SER-70)

1. Все 7 сценариев проходят подряд на чистой папке данных.
2. После демо `chain.json` возвращён в исходное состояние и валиден.
3. Повторный запуск начинает с чистой цепочки.
4. Вывод читается с проектора: короткие хеши, понятные сообщения.

## Дополнения к глоссарию

| Термин | Значение |
|---|---|
| Отчёт валидации | результат проверки цепочки: список нарушений с номерами блоков, кодами причин и сообщениями |
| Нарушение (issue) | одна найденная проблема: блок, код, сообщение, ожидаемое и найденное значение |
| Точка разрыва | блок первого нарушения, с которого цепочка перестаёт быть честной |
| Разрыв цепочки | ситуация, когда `prevHash` блока не совпадает с хешем предыдущего блока |
| Проверка внешнего файла | сверка хеша реального файла с `fileHash` в записи документа |
| `CHAIN_INVALID` | результат проверки файла, когда цепочка повреждена и файл подтвердить нельзя |
