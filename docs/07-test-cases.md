# Тест-кейсы ядра: UC-1 и UC-2

Тест-кейсы на уровне ядра блокчейна (`app/core`), без API и интерфейса. Данные: `DOC1 = 11111111-1111-4111-8111-111111111111`, `DOC2 = 33333333-3333-4333-8333-333333333333`, `fileHash` = BLAKE2b-256 любого файла (hex, 64 символа). Если не сказано иное, цепочка создаётся заново и начинается с genesis.

## UC-1. Загрузка и регистрация документа

| № | Название | Шаги | Ожидаемый результат |
|---|---|---|---|
| TC-1.1 | Регистрация нового документа | 1. `RegisterDocument(DOC1, fileHash)` | статус `CONFIRMED`, `blockIndex` = 1, `txId` равен `recordHash` записи в блоке 1, `ValidateChain()` = true |
| TC-1.2 | Два документа подряд | 1. `RegisterDocument(DOC1, fileHash)` 2. `RegisterDocument(DOC2, fileHash)` | блоки 1 и 2, `prevHash` блока 2 равен `hash` блока 1 |
| TC-1.3 | Повторная регистрация | 1. `RegisterDocument(DOC1, fileHash)` дважды | результаты равны, новый блок не создаётся, в цепочке 2 блока |
| TC-1.4 | Некорректные данные | 1. `RegisterDocument("not-a-uuid", fileHash)` 2. `RegisterDocument(DOC1, "xyz")` | в обоих случаях `ValueError`, цепочка не меняется |
| TC-1.5 | Сохранение и загрузка | 1. Зарегистрировать DOC1 при подключённом `chain.json` 2. Создать цепочку заново из того же файла | в файле 2 блока, после перезапуска цепочка из 2 блоков и валидна |
| TC-1.6 | Альтернативный сценарий: повреждённая цепочка | 1. Зарегистрировать DOC1 2. Изменить `fileHash` записи в `chain.json` 3. Запустить заново, `RegisterDocument(DOC2, fileHash)` 4. Вернуть исходный файл, запустить заново, повторить регистрацию | на шаге 3 статус `FAILED`, добавление блоков заблокировано; на шаге 4 статус `CONFIRMED`, `blockIndex` = 2 |
| TC-1.7 | Альтернативный сценарий: сбой записи на диск | 1. Сделать так, чтобы `chain.json` нельзя было записать 2. `RegisterDocument(DOC1, fileHash)` 3. Устранить причину, повторить регистрацию | на шаге 2 статус `FAILED`, цепочка в памяти не изменилась; на шаге 3 статус `CONFIRMED` |

## UC-2. Проверка целостности документа

| № | Название | Шаги | Ожидаемый результат |
|---|---|---|---|
| TC-2.1 | Целая цепочка | 1. Зарегистрировать 4 документа 2. `ValidateChain()` | true |
| TC-2.2 | Файл не изменён и изменён | 1. Зарегистрировать хеш файла из 1000 нулевых байт 2. Посчитать хеш того же файла 3. Посчитать хеш файла с изменённым последним байтом | хеш на шаге 2 равен зарегистрированному, на шаге 3 отличается, цепочка валидна |
| TC-2.3 | Подмена записи | 1. Зарегистрировать 4 документа 2. Подменить `fileHash` записи в блоке 2 3. `ValidateChain()` | false |
| TC-2.4 | Подмена порядка и `prevHash` | 1. Зарегистрировать 4 документа 2. а) поменять блоки 1 и 2 местами; б) заменить `prevHash` блока 2 с пересчётом его хеша 3. `ValidateChain()` | false в обоих случаях |
| TC-2.5 | Ручная правка файла | 1. Зарегистрировать DOC1 2. Изменить `hash` блока 1 в `chain.json` 3. Запустить заново | цепочка заблокирована (`is_blocked`), `ValidateChain()` = false, ошибка в логе |
| TC-2.6 | Нечитаемый файл | 1. Записать в `chain.json` некорректный JSON 2. Запустить | цепочка заблокирована, `ValidateChain()` = false, файл остался без изменений |
